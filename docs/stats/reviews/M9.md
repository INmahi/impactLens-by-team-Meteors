## BLOCKERS

### B1. The ice-loss-rate direction is backwards to a reader (variable name and rate verdicts)

- **Where:** `pipeline/synthetic/config.py:357` `name="Ice loss rate"` (shows in `variables.json`); `apps/web/src/content/variables.ts:70` `title: 'Ice loss rate'`; `variables.ts:50` (`ICE_SHEET_RELATES`); `apps/web/src/lib/verdict.ts:58-59`; `verdict.ts:136-155`.
- **Problem:** In the data, negative means loss (Greenland 1972 is +111 Gt/yr and recent years are negative, and `variables.ts:73` says "A negative value means the ice sheet lost ice"). So a "loss rate" that is negative when ice is lost is a double negative. The engine gives a Greenland slope of -5.32 Gt/yr per year (p < 0.001), which means **loss is speeding up**. The app currently shows: "Ice loss rate of Greenland has been trending downward by about 5.32 Gt/yr per year: the change is speeding up or slowing down over time." Anyone would read "loss rate trending downward" as loss slowing down, which is the opposite of the result. The compare code has the same problem: when both slopes are positive it says "{A} is rising faster than {B}", and in `different_directions` it says "{A} is rising while {B} is falling" for a rate. That breaks rule 9.
- **Fix 1 (name):** rename the variable everywhere it is shown.
  - `pipeline/synthetic/config.py:357` (and the matching real-data entry in `pipeline/ingest/docs.py`): `name="Ice mass change rate"`
  - `variables.ts:70`: `title: 'Ice mass change rate',`
  - `variables.ts:50`:
    ```ts
    'Ice mass change rate (Gt/yr) is how much the mass changes each year; negative means ice was lost. A trend in this rate means loss is speeding up or slowing down. ' +
    ```
- **Fix 2 (single-series verdict):** replace `verdict.ts:58-59` with:
  ```ts
  if (rep.kind === 'rate') {
    // ice_mass_rate: negative = loss, so a downward trend means more loss each year.
    headline = up
      ? `${subj} has been trending upward by about ${fmt(Math.abs(s.perYear))} ${u}: each year's change is moving toward less loss (ice loss is slowing down).`
      : `${subj} has been trending downward by about ${fmt(Math.abs(s.perYear))} ${u}: each year's change is moving toward more loss (ice loss is speeding up).`
  }
  ```
- **Fix 3 (compare):** in `compareVerdict`, handle rate series before the generic headline. Insert after `verdict.ts:148`:
  ```ts
  if (isRate && rep.verdict === 'different_directions') {
    const [spd, slw] = a < 0 ? [A, B] : [B, A]
    return { tone: 'significant', headline: `${spd.name}'s ice loss is speeding up while ${slw.name}'s is slowing down.`, detail, notes }
  }
  ```
  and replace `verdict.ts:155` with:
  ```ts
  if (isRate) headline = `${fast.name}'s ice loss is ${sFast < 0 ? 'speeding up' : 'slowing down'} faster than ${slow.name}'s.`
  ```
  `verdict.ts:143` (cannot tell apart, rate), to match wording.md:
  ```ts
  ? `Cannot tell yet whether ${A.name}'s ice loss is speeding up faster than ${B.name}'s.`
  ```
  (`ice_mass_rate` is the only `kind: 'rate'` variable. If another rate variable is added later, this text has to become variable-specific.)

### B2. A temperature correlation for Antarctica does not include the required ocean sentence (rule 4)

- **Where:** `apps/web/src/lib/verdict.ts:165-175` (`correlationText`) and `apps/web/src/panels/RightDrawer.tsx:280`. `regions.json` gives `antarctica` no notes, so nothing else adds the sentence. Demo case 2 (`docs/copy/demo-cases.md:17`) tells the presenter to do exactly this: Antarctica plus "More variables" plus "Summer air temperature".
- **Problem:** Rule 4 says every temperature correlation or sensitivity for Antarctica must carry the ocean sentence. Right now, if the detrended correlation is significant, the app shows "the year-to-year ups and downs of ice mass and summer air temperature move together" for Antarctica without it.
- **Fix:** add a region argument and append the sentence.
  ```ts
  export function correlationText(X: Variable, Y: Variable, c: CorrelationReport, r?: Region): string {
    const antarctic = !!r && /^antarctica/.test(r.id) && (X.id === 'temperature' || Y.id === 'temperature')
    const tail = antarctic
      ? ' Antarctic ice loss is driven mainly by warm ocean water reaching West Antarctic glaciers; this association with air temperature is not a melt mechanism.'
      : ''
    return body(X, Y, c) + tail   // body = the current three-branch text, unchanged
  }
  ```
  `RightDrawer.tsx:280`: `correlationText(v, xv, x.correlation, r)`.
  Add the same sentence to the "Variables together" chart subtitle (`buildChart.ts:378`) when `r.id` starts with `antarctica` and one of the items is `temperature`.

## SHOULD-FIX

### S1. A rate series' trend is called "the rate" (rule 9)
`verdict.ts:52`, `:77`, `:103`, `:108` all say "rate" for the slope of `ice_mass_rate`. Use `const what = rep.kind === 'rate' ? 'speed-up or slow-down' : 'rate'` and:

- `:77` (rate kind) `\`At this pace the yearly change shifts by about ${fmt(Math.abs(rep.slope.perDecade))} ${u} every decade.\``
- `:103` `If the current trend (${fmt(d.slopePerYear)} ${u}) and the year-to-year noise continue, ...`

### S2. "Unlikely to be chance alone" misstates what a p-value means
`verdict.ts:68` and `docs/copy/demo-cases.md:11` ("very unlikely to be chance"). A p-value is the probability of data this extreme if there were no trend, not the probability that the result is chance. NASA judges will notice. Replace `verdict.ts:68` with:
```ts
detail: `${span} (${interval}). ${rep.test.p < 0.001 ? 'A trend this strong would be very unlikely if there were no real trend' : 'A trend this strong would be unlikely if there were no real trend'} (${formatP(rep.test.p)}).${lowPower}`,
```
Demo case 1: "...and the test says a difference this large would be very unlikely if the two trends were the same."

### S3. The low-power sentence reads wrong on a significant result
`verdict.ts:44-46`. "A real trend could still be missed" contradicts a significant verdict. Keep the rule 7 sentence for not-significant results only, and use this when the result is significant:
```ts
const lowPower = !rep.lowPower ? '' : rep.test.significant
  ? ` With only ${Math.round(years)} years of data, the size of this trend is uncertain; a few unusual years can move it.`
  : ` With only ${Math.round(years)} years of data, a real trend could still be missed.`
```
(Add this variant to wording.md rule 7; I will do that in the next stats-owned change.)

### S4. The cumulative note points to a rate series that does not exist
`verdict.ts:80`. `ice_mass_long` has no rate series. Use:
```ts
out.push(hasRate
  ? 'This is a running total, which always looks like a strong trend; the slope is the average rate over the period. The ice mass change rate series shows whether the change is speeding up.'
  : 'This is a running total, which always looks like a strong trend; the slope is the average rate over the period. It does not show whether the change is speeding up.')
```

### S5. "Rise felt on the coast is larger" is also shown where land is rising
`verdict.ts:87-89` and `:158`. The regex `/subsid|sinking/` matches the North Sea and Mediterranean note "Land movement (sinking or rising coasts) is not included." Parts of the North Sea coast are rising (post-glacial rebound), so "larger" is wrong there. Replace both places with:
```ts
const ns = r.notes ?? []
if (ns.some((n) => /subsid|is sinking/i.test(n))) out.push('Land sinking is not included, so the rise felt on the coast is larger.')
else if (ns.some((n) => /land movement/i.test(n))) out.push('Land moving up or down is not included, so the rise felt on a coast can be larger or smaller than this.')
```

### S6. Compare headlines name the region, not the quantity
